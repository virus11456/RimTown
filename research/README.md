# 借錢情境的小批研究準備

目前只支援離線手寫回應。未選定研究模型，沒有供應商 HTTP adapter 或金鑰讀取；`mode: live` 會在傳送前拒絕。研究接口是獨立 Node 模組，不載入遊戲。不是 D2，也不執行角色行動。

## 配對資料

`loan-pairs.json` 是生成後保存的人工小世界快照，共四份，每份重複三次。人物、現金 50、借款請求 30、選項和好感等設定保持相同：

| 版本 | 唯一改動 | 連帶資料 |
|---|---|---|
| baseline | 無 | 無 |
| repaid_memory | 本人記得阿華曾依約還款 | 記憶來源編號、知識版本 |
| known_expense | 本人已確認孩子明天看病由自己付 40 | 支出、確定算術、狀態版本 |
| stated_purpose | 阿華親口說要修屋頂 | 本人聽到的說法、知識版本 |

醫療日期與付款安排是明確建立的研究事實，沒有從遊戲健康表取得，不能宣稱遊戲已具備醫療預約或知情紀錄。候選行動與金額範圍相同；差異清單存於資料的 `pairs`。借款金額固定，避免舊流程從放款人現金產生金額的側漏。

送給評估器的只有 input 與契約說明，沒有版本處理名稱、配對目的、repeat、稽核紀錄或期望答案。每次請求獨立，重複時不讀取結果快取、不累積前次對話。程式固定輸入順序但不把前一份回覆帶入下一份；此小樣本不適合估計人口層級效果。

## 接口與紀錄

`scripts/psy_research.js` 將 appraisal、choice、supplement、confirmation 四個階段都接到同一個 transport.send(request)。提供給 transport 的 request 含契約提示、凍結輸入、該階段可用的評估／初步提案與輸出上限。transport 預期回傳 `{value, usage:{input_tokens,output_tokens}}`；錯誤透過 D1 核心成為技術待處理。模型 id、渠道和設定記錄在研究紀錄，不當成人格資料。

現有 transport 全部是 `TEST_FIXTURE_HANDWRITTEN`，固定拒絕，不根據處境預設角色反應，也不能當正式後備。測試另有一份人工回應驗證補評估與確認會通過同一個預算入口。

紀錄含每次 request、hash、原始回應和 usage；`replayTransport` 按順序及 request hash 精確重播。現在只允許重播手寫紀錄；真實渠道、真實回應錄製的標記與重播支援需要後續授權接入，不能把它們標成手寫回應。

## 預算控制

`config.json`：假設上限 US$5（5,000,000 micro-USD）、最多 60 次呼叫、每次最多 4096 輸出 token。費率暫用輸入每 token 4 micro-USD、輸出 20 micro-USD，僅是離線控制測試假設，模型仍為 UNSET；不是已選模型或當日報價。

- 每個階段呼叫前，依請求 UTF-8 位元組數加 1024 預留輸入額度，搭配最大輸出上限預留成本。這是離線保守估算，不是供應商 token 計數的證明。
- 所有階段、失敗與任何未來重試都須經同一入口；目前沒有自動重試。名額或預算不足時不傳送，不替角色選答案。
- 只有有效 usage 才結算並退還差額；失敗、逾時、崩潰或 usage 缺失保留預留額。意外超出預留會記帳並鎖住後續呼叫，無法追溯阻止已發生的超額。
- CLI 使用獨占鎖及原子替換的 budget.json，重新執行不會重設累積額度。崩潰留下鎖時須人工確認沒有其他程序，再處理鎖；不可自動刪鎖或改成新研究繞過上限。
- 這是本機研究批次控制，不是帳戶整體支出保證。未來啟用真實 API 前，需核實實際模型／費率／計費項目、token 計數與輸出上限支援，另設供應商可用的帳戶控制；不得直接把 fixture 改名就連線。
- 設定檔與紀錄不得含金鑰；providerSettings 只允許 temperature、effort、seed，是否為所選模型支援仍待接入時驗證。

## 執行（全部離線）

在本資料夾上層執行：

```sh
node scripts/psy_loan_pairs.js
node scripts/psy_research_test.js
node scripts/psy_research.js
```

結果放在 `test-results/loan-research-fixture/`。同一批重跑會繼續累積模擬額度，輸出另外建檔，不覆寫上一批。此環境的 Node 位於 `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node`。

## 將來的人工判讀

先檢查是否注意到可知變動、引用是否支持評估、是否區分事實／推測／承諾，以及提案是否一致，再比較理由和選擇。可以選擇不變；不以「醫療支出必須拒絕」等答案驗收。相同輸入的三次回應用來觀察模型變異，不將模型變異解釋成人格變化。

手寫回應的通過只代表流程可運作；本批沒有真正測得人物會因經歷改變。手動插入記憶的配對，也不能證明遊戲中經歷形成記憶後的完整行為鏈。
