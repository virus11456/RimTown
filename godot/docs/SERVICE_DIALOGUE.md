# 居民服務結果與對話

照護／談心先前只有工作面板的結果，居民交談未收到同一份事實。本包把實際服務狀態接到居民行程、本機詢問與三種生成回覆通道。

## 如何使用

居民 → 交談 →「詢問服務結果（本機）」。不連線、不消耗 AI 額度；保留輸入草稿，相同資料連續詢問不重複寫入。今日行程也會顯示服務狀態和最近結果。

進行中明示尚未完成，並區分有無接受短暫停留。完成後才致謝；取消時說明未完成與原因，例如需要先吃飯、休息、上工、避難或見面行程。台詞依已記錄的理由表達，不把「需要上工」說成「已走到工作場所」，不替距離拉開推定誰失約。原始原因仍保留供行程與生成通道核對。

## 紀錄來源與限制

只在醫護／牧師真正完成或取消時保存結果，午夜換日取消也會記錄。拒絕開始不算接受過服務，重複結算不增加紀錄或獎勵。全鎮最多 64 筆，單一居民對話讀最近兩筆；新結果有流水識別，避免同一 tick 連續中斷被當成同一份舊資料。截斷後不保證永久保留較早的服務。

舊存檔未記錄的結果不從技能、總完成數或文字猜測補回；沒有資料就如實說沒有可核對紀錄。本包沒有增加資源、技能、好感或每日服務次數。本機回答及其事實來源跟著原生存檔保存。

自由聊天、事件評論與友情真心話均包含同一份有界服務資料。等待回覆期間，該居民的服務開始、完成或取消會使舊資料失效：自由聊天整份舊回覆與效果不套用、草稿保留；主動通道回到原事件本機台詞，不產生舊邀約。單純時間經過或其他居民的結果不會誤擋。本包以 mock 驗證回呼，沒有呼叫正式 AI，也不宣稱任意模型回覆都能正確理解資料。
