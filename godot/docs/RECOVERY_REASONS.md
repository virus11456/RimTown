# 恢復中止原因與後續追蹤

2026-09-13。

恢復安排中止時保存明確原因代碼與說明，區分上工、通勤、正常睡眠、返家作息、已確認約定、休閒／同行安排、玩家服務、飢餓、疲勞、避難、搬家、期限、跨日、未按時到家、已離家，以及功能／居民狀態失效。多條件同時成立時依既定優先順序取首個原因，不猜測單一因果。

居民回憶沿用結果中的原因代碼，以「那時需要上工」等措辭說明，不聲稱已完成工作或赴約。旧結果沒有代碼時保留一般中止說法，不反推當年的原因。死亡等無法再更新日常行程的居民，其未結束恢復安排也會清理。

結果產生後下一刻，只保存一次觀察：實際位置、座標與當時行動意圖。意圖與到場證據分開，介面不把「要去工作」改寫為「已到工作地點」。舊結果若已錯過這一刻，不補造歷史位置；讀檔後已存在的觀察不覆寫。

318 項控制檢查涵蓋具體中止原因、同源回憶、失效居民清理、上工意圖與物理位置分離、結果與觀察去重、讀檔、既有恢復和近身搭話；17 組相關回歸涵蓋照護、恢復、搭話、約定回憶、睡眠與守衛。沒有改動步速、恢復速度、照護效果或每日限量。

報告見 RECOVERY_REASONS_TESTS.json、RECOVERY_REASONS_REGRESSION.json、RECOVERY_REASONS_NATURAL_HARBOR.json、RECOVERY_REASONS_CAPTURE.json、RECOVERY_REASONS_DELIVERY.json。原生畫面為控制完成／上工中止情境；交付包沿用先前兩份四日進度存檔，未重新生成交付進度。
