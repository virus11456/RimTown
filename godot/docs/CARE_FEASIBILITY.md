# 求助前的路程與空檔判斷

2026-09-13。本包先減少無法完成的出發，下一包改善可用接待時段。

居民先檢查可通行路線，依正常步行預算估算抵達時間，再預留到場確認與兩刻照護。預估為路程除以步行預算向上取整，加三刻；仍須小於原本八刻期限。還會檢查服務者是否持續在班、雙方是否需要先吃飯或休息、居民上工與睡眠空檔、已確認約定及返家路程。

條件不足時，行程頁顯示具體暫緩原因，不改變居民座標、不扣每日求助次數；條件恢復可再次判斷。這是保守預估，途中事件仍可能中止服務。照護效果、每日限量、步速及守衛班表沿用既有規則。

## 驗證與限制

新增 40 項控制檢查，涵蓋臨近下班、飲食體力、不可通行路線、約定、期限、暫緩後再次求助。兩個既有步行整合測試改從接待點附近出發，以符合新增可行性條件；仍實際走路、到場、停留及讀檔。

兩鎮各四日、各 184,320 個移動影格，包含中途讀檔與接地、碰撞、作息及限量檢查。邊境鎮無求助；港鎮無實際出發、無完成、無中止，五位居民留下十二筆居民／日暫緩，皆為超過路程與照護期限。上一包同樣四日港鎮有六筆中止。此結果支持減少白跑，不代表自然照護已成功或平衡完成。

四張原生畫面為控制需求與臨近下班情境，確認行程頁的暫緩提示，不當作自然模擬成果。試玩包沿用先前兩份四日進度存檔，本次沒有重新生成進度存檔。
