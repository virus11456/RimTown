# 居民主動提起服務回憶

居民原本只能在玩家詢問時說明服務結果。現在近身閒聊也能提起最近的照護或談心：已完成會致謝，取消則明說沒有完成並說明實際原因，不建立新的邀約。

## 觸發與防重複

沿用既有主動聊天條件：同一場所／住家、三格內、清醒且需求穩定、不在工時、玩家沒有正在值勤或等待事件／聊天回覆。打開交談頁時也不插話。每日全鎮最多兩次、四小時間隔、同居民每日一次，與原本問候共用額度，不另開配額。

只取該居民最新服務結果，完成至少一小時、距今不超過兩個遊戲日才可回憶。新取消會取代舊完成；尚在進行、未記錄時間、過期或單純文字記憶不作為完成證據。已有玩家約定回憶優先，其次服務，再來是私人休閒。

同一份結果只主動提起一次。識別沿用有界的已回憶紀錄；新資料使用流水號，較早的已驗證服務資料以標準化事實產生識別，整數／浮點數的 JSON 重載差異不會讓它重講。讀取候選回憶不改世界；真的在現場搭話才記入聊天、雙方記憶和已觸發紀錄。

本機規則，不使用 AI 額度，不增加物資、技能、好感或服務次數，不消耗模擬亂數。這不是生成式反思，也不承諾任意生成回覆都正確。

## 驗證範圍

受控核心案例涵蓋醫護／牧師的完成與取消、時效、來源、雙方記憶、防重複、每日上限、冷卻、進行中服務、不同居民、舊識別與 JSON 重載。原生介面測試使用先前自然四日存檔的真實結果，但刻意安排清醒、空閒與需求條件；沒有直接搬動 NPC，必要時讓他按現有路徑走完，再讓旅人以碰撞移動接近。介面涵蓋完成／取消台詞、等待回覆時延後、375px 與壓縮存檔重載。

另從兩鎮原始新局各跑四日，旅人以正常移動完成服務後，再尋找可回憶的居民；不修改 NPC 需求、職業或座標來製造遇見。細節見 SERVICE_RECALL_NATURAL_FRONTIER.json 與 SERVICE_RECALL_NATURAL_HARBOR.json。存讀檔先讓旅人停步，避免把載入後正常清除行走按鍵／動畫誤認為位置遺失。

完成 1,253 項檢查：核心 48、原生介面與回覆等待 39、十六組回歸 1,120、兩鎮自然四日 22、交付存檔 24。

自然四日合計 368,640 運動影格。邊境鎮完成照護 9 次、主動服務回憶 2 次；港灣鎮完成照護 3 次、回憶 1 次。沒有重複回憶、瞬移、不可通行落點或負庫存，原始 NPC 職業及自家睡眠保持。自然情境沒有低落陪伴需求，牧師回憶由受控案例覆蓋；不宣稱自然牧師通關或整體照護成功率改善。

附 `主動回憶四日_frontier.rimtown`、`主動回憶四日_harbor.rimtown`。實際匯入後，主動回憶來源、已觸發識別、技能／完成數與完整重載均通過。另產生的「回憶測試場景」含受控職業與需求，不當成自然進度交付。
