# 照護接待資訊與班表試驗

2026-09-13

## 玩家操作

居民 → 選擇居民 → 今日作息與行程 → 查看照護接待。

每位醫護／牧師分開顯示：原有排班與接待地點、目前實際位置、是否到場、是否已有居民赴診或接受照護、當日剩餘完成額度。未上班時顯示下一次排班；排班不等同保證在場。

「這位居民」依選定居民的需求、既有求助／恢復、每日同類服務與求助次數、優先行程及完整赴診路線，說明目前可行性。需要返家準備時，沿用上一包完整準備時段檢查。沒有醫護／牧師、缺少設施或位置資料時明確說明。

時間推進會更新頁面，可返回原作息頁。此頁不預約、不扣次數、不重設跨日額度，不指揮旅人或居民；正向提示只是當下初步評估，正式出發仍依模擬判斷。

## 驗證與限制

84 項專項及 11 組回歸通過，涵蓋兩鎮兩種照護角色、到場／走動、下班／隔日、額度已滿／昨日額度、正在赴診、玩家與居民共用同類服務限制、缺設施／觀察、畫面零副作用、頁面往返、時間推進與實際讀檔。交付舊四日進度匯入 22 項通過。

桌面 1280×800、手機 375×812 原生渲染已檢查。圖片使用可重現的受控角色／設施／需求，不是自然赴診成功證據。

原先試驗將醫護工時從 08:00–18:00 整體延後至 10:00–20:00，海風鎮四日仍沒有赴診或完成；保留的 18 筆暫緩皆為無法趕上服務者下班。這個試驗只在記憶體修改規則，沒有採用到正式班表。不能據此認定延長或延後工時可以解決問題，也未放寬每日限量。

下一步應逐段檢查自然需求出現、用餐和回程餘裕，找出確實需要服務且能完成的時段；不為提高完成數強迫居民赴診。
