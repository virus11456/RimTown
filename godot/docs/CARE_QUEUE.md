# 照護候補與路程修正

2026-09-13。此包改善接待空檔分配，尚未建立跨日預約。

## 行為

居民有需求、路程與當前行程可行，但服務者正在接待別人時，加入當日候補。先候補者優先重新檢查，時間相同才以穩定名單順序決定；若還有其他服務者可接待，仍可直接出發。

候補只是等候機會，不保證時間或名額。不會移動或凍結居民、不花費每日求助次數；空檔出現時重新核對實際位置、需求、工作與睡眠、約定、返家時間以及雙方限量，再正式出發。跨日、睡眠／必要行程、需求消失或關閉社交時清除候補。候補時間跟隨存檔保存。

出發前估算改為與移動程式一致的出口、目的地入口、實際接待點。之前經由建築中心再回到服務者，會多算實際不走的路程。同室直接計算到接待點。八刻期限、正常步行預算、照護效果與每日限量不變。

## 驗證

55 項兩鎮醫護／牧師的控制檢查涵蓋忙碌時候補、先後順序、等候不凍結、次數不扣、原服務完成後接續、實際存檔載入後再接續，以及跨日、睡眠、關閉社交與門口路線。原生四張行程頁截圖確認候補提示。

自然模擬與完整回歸結果見同目錄 CARE_QUEUE_REGRESSION.json、CARE_QUEUE_NATURAL_FRONTIER.json、CARE_QUEUE_NATURAL_HARBOR.json。控制情境成功不等於自然居民已完成照護。

試玩包沿用前次兩份四日進度存檔，本次不重新生成交付存檔。CARE_QUEUE_DELIVERY.json 驗證舊存檔載入。
