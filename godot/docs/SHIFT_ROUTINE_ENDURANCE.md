# 讀檔作息修正、輪班長期驗證與實際上工狀態（2026-09-11）

## 讀檔作息修正

第一輪八日測試在第四日重載後，發現夜班守衛暫時退回一般夜間睡眠；第五日出現一次接班延誤。原因是 JSON 將保存的班表數字讀成浮點數，原本直接比較陣列，誤判它與相同的整數班表不同，捨棄了仍然有效的睡眠窗口。

現在逐項比較數值，保留真正相同的班表；不同時段、含小數差異或不合法的資料仍不能套用舊窗口。兩次連續原生讀檔後，比較全部 20 位 NPC 在 24 小時中每小時的睡眠判斷，確認一致，並核對手機行程頁仍顯示夜班 08:00–16:00 補眠。未修改原始存檔、角色位置、時間或資源。

## 行程頁

居民的「今日作息與行程」新增上工狀態，依有效班表與實際位置顯示：

- 工時內但不在工作場所：顯示目前不在工作場所，保留實際活動；不因 activity 是 working 就宣稱到場。
- 已在工作場所：同時說明目前活動，進食不改稱工作；進出門／移動另行說明。
- 工作場所未建成：單獨說明原因，不當成一般遲到。
- 沒有位置資料：顯示無法確認，不猜測到場或缺勤。
- 非值勤時段：不顯示缺勤提示；夜班跨午夜正確判斷，白天休息不受影響。

這是唯讀即時狀態，不是打卡或懲罰系統，也不推斷先前是否準時。開局第一小時距離較遠的居民照常走路，沒有移動起始位置、加速或瞬移。

## 驗證範圍

手機行程頁用原始開局步行到 07:00，確認尚未到採石場的居民明確顯示不在工作場所；另外測試跨午夜、進食、門口、非值勤、缺設施／位置，以及玩家／死亡狀態。讀取面板前後世界與移動資料完全一致。

八日耐久驗證沿用原始場景 768 ticks，每 tick 480 移動 frames；第四日中途以原生存檔重新載入，檢查班次與同行紀錄。逐 tick 核對睡眠是否真的停在自己房間，逐 frame 核對同行見面位置和返家步行，逐次班表開始記錄實際工作場所。

實驗為 headless 場景模擬，未呼叫正式 AI，也未宣稱全遊戲自然通關。只有邊境鎮這份初始資料的結果，不能保證所有城鎮／任意存檔長期皆準時。準時到場以工作場所範圍判斷，不等於連續全班都在執勤。

測試結果見 `SHIFT_ROUTINE_ENDURANCE_TESTS.json` 與 `ATTENDANCE_UI_TESTS.json`；歷史兩日與八日資料保留，不覆寫為本包結果。

剩餘三筆不準時都在開局 07:00：吳達、馬強、何昌由原始位置行走尚未到場。第 2–8 天所有具備工作場所者準時；沒有觀察到假冒在家睡眠，同行後返家最大單 frame 位移約 0.984 像素。上述社交次數是兩次完整模擬的觀察值，並非宣稱此修正單獨提高社交頻率。
